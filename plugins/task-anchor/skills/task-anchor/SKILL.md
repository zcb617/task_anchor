# Task Anchor

把用户显式调用本 Skill 的消息视为当前 Codex 任务的初始任务指令。

## 起始动作

1. 在开展实质工作前，使用 Codex 原生 TOLIST 建立当前任务计划。
2. 让计划覆盖目标、必要步骤和验证工作；不要创建自定义 TOLIST 文件或任务数据库。
3. 如果初始任务指令引用前文方案或文件，先读取当前可见上下文或对应文件，再把具体执行步骤落实到原生 TOLIST。

## 持续工作

- 每当一项工作开始、完成或阻塞时，立即更新 Codex 原生 TOLIST。
- 用户明确修改目标、约束或执行方向时，立即更新原生 TOLIST；较新的明确用户指令优先。
- 只在任务状态发生实际变化时更新，不因普通工具调用机械更新。
- 不调用 MCP、小模型或子代理来维护任务状态。

## 压缩后恢复

本插件通过 `PostCompact` Hook 在每次成功压缩后立即重新注入最初任务指令；不依赖下一条用户消息，也不同时配置 `SessionStart(source=compact)`，以避免重复注入。

## 项目边界

- 显式调用时，插件会把当前项目身份的哈希与任务锚点一起保存：Git 项目使用仓库根目录；非 Git 目录使用规范化工作目录。
- 每次 `PostCompact` 恢复前，插件都会核验当前项目身份仍与锚定时一致；同一 Git 项目的不同子目录不会误判为跨项目。
- 项目身份不一致、Hook 未提供 `cwd`，或旧记录没有项目边界绑定时，插件会拒绝注入，而不是把旧项目的指令带入新项目。
- 需要在另一个项目继续工作时，必须新建任务并重新显式调用 `$task-anchor`。

当额外上下文要求使用本 Skill 继续当前任务时：

1. 重新读取其中的“最初任务指令”原文。
2. 将其作为当前任务不变的起点。
3. 继续已有的 Codex 原生 TOLIST；不要另建任务清单。
4. 从当前未完成事项和下一步继续工作，不重新解释或改写最初任务指令。
